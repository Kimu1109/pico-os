# キャリアボード(`hardware/carrier/`)

> 何がどこにあるかの地図は `CLAUDE.md`、使い方と部品の表は `hardware/carrier/README.md`。

## v0.1 の初版 (2026-11-02)

今までジャンパワイヤでつないでいたモジュールを1枚に載せる基板。KiCad 8、2層。

### 利用者と決めたこと

- **モジュールを載せる「親基板」**(チップを直接載せる形ではない)。最初は機能をほとんど持たせず、つなぐだけ。
- **キーボード(CardKB2)は今までどおり Grove のケーブルでつなぐ**。基板に作り込まない。
  空きGPIOが0本(GP8/GP14で使い切った。`sound.md`「イヤホンとスピーカーの切り替え」)なので、キーを直接読む形はもともと取れない。
- **LiPo SHIM は Pico に重ねず**、Pico と同じ番号のピンを基板の上で結ぶ。電源ボタンで切れるのは 3V3_EN だけ。
- **SD は液晶(MSP2807)のスロットを使う**(SPI1 の GP10/11/12/15 のまま)。別のSDモジュールはやめた。
- 液晶・CardKB2 の電源は今の構成(全部載せ)で問題が出ていない。電池が10%を切ると電圧が下がって再起動を繰り返す症状はある。
  配線が短くなるぶん良くなる見込みだが、直らなければファーム(電池での音量の頭打ち・自動で電源を切る)で手当てする。
- KiCad の版は Claude Code が選んだ(8。9 でも開ける)。

### 決めた形と理由

- **液晶を表、ほかは全部裏**。液晶(50x86)の下の11mmほどのすき間には電池(厚さ10.3mm)が入りそうに見えるが、
  液晶の裏のSDスロット(左の縁、約2mm)と重なるので入らない。電池はケースの側で持つ。
- **Pico は下端に横向き、アンテナの下を切り欠く**: USB とアンテナの両方を縁に出したいので横向きにした。
  基板の幅は56mmで Pico(51mm)より長いので、アンテナの下(ピンの2列の間)を切り欠いて銅も基板も無くした。
- **電源の切り替えはジャンパー**: 液晶・PCM5102A・CardKB2 は 3.3V と VSYS のどちらからでも動くので、3パッドのはんだジャンパーで選ぶ(既定は 3.3V)。
  RTC・Qwiic・マイクは 3.3V に固定(RTC モジュールのプルアップが VCC に付いているので、5V にすると I2C が5Vへ引かれる)。
- **GP5(アンプの検出)は JP6 で GND へ**: モジュールが基板に常に載るので、抜き差しの検出は要らない。
- **CardKB2 の UART モード**: 白線を JP4 で GP1(SCL)と GP7 から選ぶ。黄線は JP5 で切れる
  (UARTモードの CardKB2 の RX が I2C の SDA に乗っていると、Wii の通信を拾ってしまうため)。
- **イヤホンの差し込み検出は J3(2ピン)へ配線**: PCM5102A モジュールのジャックに検出の接点があるかが分からないので、
  ジャックは基板に載せず、検出の接点から線を引く口だけ置いた。
- **C1(100uF)を VSYS に1つ**: 電池で MAX98357A を鳴らしたときの電圧の落ち込みを少し和らげる(`battery-touch.md`「音割れ対策」)。

### 寸法の出典

- 液晶: lcdwiki の `MSP2807_Size.pdf`。50x86、M3の穴(φ3.2)は角から3mm・間隔44x76.08、14ピンは左から8.49mm・下から2mm、
  SDの4ピンは上から3mm・右から21.19mm(表から見て。SD_CS が左端)。
- 電池: LP103454(34.5x56x10.3、JST PH 2ピン。利用者が極性を入れ替え済み)。
- LiPo SHIM(PiCoLiPoSHIM、2026-11-02 に商品写真で確認): 21x21、穴は片側8つで Pico の 1〜8・33〜40番の位置(当初7つと読み違えていた)。
  部品(JST・ボタン)は文字の無い面。文字の面が Pico の裏と向き合うので、部品面から見た並びは Pico の鏡映(1番が右上、ボタンの端が上)。
- DS3231(ZS-042、2026-11-02 に商品写真で確認): 38.2x21.6、短い辺に 32K/SQW/SCL/SDA/VCC/GND。ピンはチップの面から出るので、
  電池の面を外へ向ける形にした(外から見るとピンの並びは上下が逆になる)。商品写真の物は L字のピンで、まっすぐなピンへの付け替えが要る。
- PCM5102A(GY-PCM5102、2026-11-02 に商品写真で確定): 32x17。短い辺に SCK/BCK/DIN/LCK/GND/VIN、長い辺に(部品面から見て左から)
  FLT/DEMP/XSMT/FMT/A3V3/AGND/ROUT/AGND/LROUT。裏の印字(LROUT〜FLT)を左右反転した並びと一致する。裏の H1L〜H4L は FLT/DEMP/XSMT/FMT を
  GND へ落とすはんだジャンパーで、**XSMT(H3L)は盛らない**(GP14 が GND とぶつかる)。ジャック PJ-327A の1番は基板上で未接続。
  裏の部品は反転で向きが180度になるので、`gen_carrier.py` では `turn=180` でジャックを基板の右の縁へ向けた。
- MAX98357A(TVETE、2026-11-02 に商品写真で確認): Adafruit 3006 と同じ形。18x19、18mm の辺に LRC/BCLK/DIN/GAIN/SD/GND/VIN、
  反対の辺に端子台。部品面から見てピンの列を上にすると左から VIN〜LRC(当初は左右を逆に置いていた)。
- SPH0645(Adafruit 3421、12.7x16.7、2026-11-02 に Adafruit の写真と実物で確認): 音の穴は基板の裏で、Adafruit も「マイクを下、穴を上」に
  裏返して付ける前提。外から見える穴の面でピンの列を左にすると、上から SEL/LRCL/DOUT/BCLK/GND/3V。

### 作り方と確かめ方

- `hardware/carrier/tools/gen_carrier.py` が部品・結線・置き場所の表から記号・形・回路図・基板を作った(初版だけ。以後はKiCadのファイルが一次情報源)。
- ERC 0件。`tools/check_pins.py` で全モジュールの端子が `consts.hpp` の GP と一致することを確かめた(36項目)。
- 配線は `tools/route_carrier.py`(2026-11-02、利用者の「余裕を持って、とにかく動くことを優先」に合わせた)。
  Freerouting はクラウドの環境で実行できなかったので、KiCad の Python だけで動く格子(0.5mm)の迷路探索を書いた。
  信号0.4mm・電源1.0mm・間隔0.3mm・縁から0.5mm・ビア0.8/0.4mm、表は横・裏は縦が主。つながらなかったネットを先頭に回して
  やり直し、全部つながった回を残す(8回目で全ネット)。DRC(回路図との照合込み)・ERC とも違反 0。
- **配線のために外形を 56x116 から 64x128 に広げた**: Pico の2列のピン(2.54mm間隔)の間は 0.4mm の線が通れないので、
  下の列のピンからは「左の端」か「下の縁との間」からしか出られない(右はアンテナの切り欠き)。左の通り道が6mm・
  液晶の14ピンの列と Pico の上の列の間が6.6mmでは詰まったので、Pico を右(切り欠きの側)へ寄せて左に約13mm、
  液晶の列との間を約16mm 空けた。
- 線で区切られたGNDのベタの島に掛かる端子は、島ごと全面でつないだ(DRC の starved_thermal を消すため。端子は線でもGNDにつながる)。

### 実物でしか分からないこと(Todoist参照)

- LiPo SHIM を挿す向き(間違えると VBUS/VSYS が GP0〜GP5 につながる)と、DS3231 のピン(L字→まっすぐ)。

### 発注前の見直し(2026-11-02)

利用者の「ガーバーの前にもう一度確認」で、DRC に出ない物理的な所を見直して3つ直した(配線は引き直し、5回目で全ネット):

- **M3 のネジ・スペーサーの下に信号線が通っていた**(穴の中心から 2.0mm)。ネジ頭やスペーサーがレジスト越しに線を押さえるので、
  穴の中心から半径3.5mm に線とビアの禁止区域(ルールエリア)を置いた(GND のベタは残す)。配線後の最短は 3.8mm。
- **Grove(J1)と Qwiic(J2)の差し口が基板の内側を向いていた**(横向きのコネクタは本体が端子から伸びる側が差し口)。180度回して右の縁へ向けた。
- **シルクが JLCPCB の目安より細かった**(文字0.8mm、既製の部品の形の線0.12mm)。文字は1.0mm以上、線は0.15mm以上にそろえた。

ガーバーは `tools/export_jlcpcb.py`(JLCPCB の KiCad 向けの案内どおり: Protel の拡張子・X2なし・ネットの情報なし・
シルクからマスクを引く、ドリルは Excellon/mm/PTH と NPTH を別)。書き出した物を gerbv で描いて、外形・切り欠き・穴・ベタを目で確かめた。

## v0.2: 余裕のある配置へ (2026-11-02)

利用者から「まだパンパンに見える。もっと余裕のある感じに」。v0.1(64x128)はモジュールどうしがほぼ接し、線の間隔も 0.3mm ぎりぎりだった。

- **外形を 80x140 に広げ、配置をやり直した**: 液晶を中央(左右15mm)に、モジュールどうしは数mm以上離し、M3 の穴の上にはモジュールを置かない。
  液晶の14ピンの列(y=89)と Pico の上の列の間は約19mm、Pico の左(USBの側)は約20mm、下の縁との間は約14mm。
- **線の間隔を 0.4mm、縁から 1.0mm に**(DRC の決まりは 0.3mm)。配線後の別のネットの線どうしの最小は 0.5mm。
  0.5mm にすると Qwiic(1mm間隔、幅0.6mmの端子)から線を出せず、つながらないネットが毎回4〜11本残った。
- VSYS の本線(Pico・SHIM・アンプ・C1)は 1.0mm。0.4mm になったのはジャンパー(JP1〜JP3)の VSYS 側へ分かれる枝だけ(既定ではつながっていない側)。
- 結果: DRC(警告まで・回路図との照合込み)0件、ERC 0件、check_pins.py 36項目で食い違い 0、ネジの穴から一番近い線は 3.9mm。

### 実物の確認(2026-11-03、利用者)

- PCM5102A の H3L(XSMT)にはんだは盛られていない(GP14 で切り替えられる)。
- 利用者はモジュールの付けられる所には全部ピンヘッダを付けている。マイク(文字の面が外・ピンはマイク本体の面)と LiPo SHIM(部品の面を上にして
  挿せる向き)は、この基板の前提と同じ向き。Pico 2 W は WH(ピンヘッダ付き、黒いサポート材は2列の間)で、デバッグ用の3ピンは付けていない。
  どれも基板を直す必要は無い。
- DS3231 はまだ届いていない。L字のピンで届く見込みなので、**まっすぐなピンに付け替える**(2026-11-03 に利用者と決めた。基板は v0.2 のまま)。

## v0.3: さらに余裕を持たせる (2026-11-04)

利用者から v0.2 を見て「まだ不安。もっと余裕をもたせてもいい」。v0.2 は線が最小の間隔のまま束になって走る所が多く、
長さ1mm以上の線の約23%が別の線から 0.6mm 未満だった(配線は「通れれば最短」なので、空きがあっても寄り集まる)。

- **外形を 100x160 に**: モジュールどうしは 8〜12mm 前後、液晶の14ピンの列と Pico の間は約34mm、Pico の左(USBの側)は約25mm。
- **線を太く・間隔を広く**: 信号 0.5mm、間隔 0.5mm(DRC の決まりは 0.4mm)、縁から 1.5mm。Qwiic(1mm間隔・幅0.6mmの端子)の周りだけ
  間隔 0.4mm(0.5mm だと端子から線を出せない。v0.2 で分かったこと)。
- **線どうしを離して引く**: 別のネットの銅から 1.5mm 以内を通ると少し高くする重み(`NEAR_EXTRA`/`COST_NEAR`)を配線に足した。
  0.6mm 未満の線は約11%に減った(重みを 1.0mm・0.6 にしたときは 14%)。
- **端子の上にビアを置かない**: 同じネットの THT 端子の上にビアを置いて、穴どうしが重なった(DRC の hole_near_hole)。
  端子の近く(ビアの半径+間隔)には、ネットにかかわらずビアを置かないようにした。同じ場所のビアは1つにまとめる。
- 結果: DRC(警告まで・回路図との照合込み)0件、ERC 0件、check_pins.py 36項目で食い違い 0、ネジの穴から一番近い線は 4.0mm。
