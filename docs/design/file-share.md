# Wi-Fi転送(ブラウザからSDのファイルを読み書きする)

> `CLAUDE.md`「設計記録の索引」から引く設計記録。進み具合は `SUMMARY.md`。

## Wi-Fi転送 (`src/net/File_Share` / `src/net/File_Share_Page.cpp` / `src/services/FileShare_Functions` / `FileShareScene`) (2026-10-27)

ランチャの「Wi-Fi転送」(アイコンは共有)。開いている間だけ、同じLANのPC・スマホのブラウザ(またはcurl)から
SDのファイルを一覧・ダウンロード・アップロード・削除・名前の変更・フォルダ作成できる。USBドライブと違って線が要らず、スマホからも使える。
第1段(画面を開いている間だけ・STAだけ)。APモード([スマホから直接])・`Range`・フォルダのアップロード・常駐・WebDAV は後回し。

### 方式

- **HTTP+本体が返す1枚のページ**(HTML+JS、`File_Share_Page.cpp` に生の文字列で約7.4KB)。WebDAVはファイル一覧の問い合わせにXMLで答える必要があり、
  Windowsの書き込みのロック・macOSの `._*` 等の癖への対応が重いので見送った。FTPは2本目の接続が要り、ブラウザも対応をやめたので使わない。
  ページはgzipにすれば約3KBに縮むが、生成の道具が要るので第1段は生のまま(フラッシュは今のところ余裕がある)。
- **アップロードは `PUT /f/<パス>` で、本文がファイルの中身そのもの**。フォームのファイル送信(multipart)は読むのが面倒なので使わない。
  ブラウザ側は XHR の `send(file)`(進み具合が要るので fetch ではない)、curl は `-T`。`Transfer-Encoding: chunked` は断る(どちらも Content-Length を付ける)。
- 取り決め(`net/File_Share.hpp` の先頭):

  | 要求 | 中身 |
  |---|---|
  | `GET /` | ページ。キーは要らない(中身を持たない) |
  | `GET /api/info` | `{"name":"<本体の名前>"}`。ページはこれでキーを確かめる |
  | `GET /api/ls?p=/music` | 1行1つ `名前\t種類(f/d)\t大きさ`。長さを付けずに閉じて終わる(何件でも1KBずつ詰めて送れる) |
  | `GET /f/<パス>` | ダウンロード(`?dl=1` で `Content-Disposition: attachment; filename*=UTF-8''…`) |
  | `PUT /f/<パス>` | アップロード(Content-Length 必須、411) |
  | `POST /api/mkdir?p=` / `rm?p=` / `mv?p=&to=` | 作成・削除(フォルダごと)・名前の変更/移動 |

### 守り

LANの中の平文のHTTPなので、「同じWi-Fiの誰でも書き込める」状態にしないことを一番に置いた。

- **キー**: 画面を開くたびに作る8文字(`SecretAead::Random`、紛らわしい 0 1 l o i を抜いた31字で約8.5×10^11通り)。
  画面に大きく出し、右のQRには `http://<IP>/?k=<キー>` を載せる(ページのJSがクッキー `pk` へ移して URL から消す)。
  `/api/*` と `/f/*` はクッキー `pk` か見出し `X-Pico-Key` のどちらかが合えば通す。curl は見出しだけでよい。
- **書き換える要求(PUT/POST)は見出し `X-Pico-Key` が必須**(クッキーだけでは403)。ほかのサイトのページが本体へ書き換えを送ろうとしても、
  独自の見出しを付けるとブラウザがCORSの事前確認(OPTIONS)を先に送り、本体はそれに答えない(405)ので本番の要求は出ない。クッキーは `SameSite=Strict` も付ける。
- **間違ったキーが5回続いたら30秒全部断る**(429、`FileShare::Throttle`)。正しいキーの人もその間は待たされるが、LANの中の話なので総当たりを遅くするほうを取った。
- **`Host` が本体のIP・`<名前>`・`<名前>.local` 以外なら403**(DNSリバインディング: よその名前を本体のIPへ向けて、ブラウザに本体を「同じサイト」と思わせる攻撃)。
- **パス**: `%XX` を戻してから名前ごとに `PICO_IO::isValidName()`、`PICO_IO::normalize()` で畳む(ルートを超える `..` は捨てるので、SDの外へは出ない)。
  **`/sys` とその中は一覧に出さず、読み書きとも403**(`lock.cfg`・`wifi.cfg`・`*_token.cfg` 等の鍵・トークンの置き場)。FATは大文字小文字を区別しないので `/SYS` も同じ。
  `%73ys` や `a%2F..%2F..%2Fsys` のように隠しても、戻して畳んだ結果で比べるので断る。
- 画面ロックの間は受けない(423。ロックしたら途中の転送もやめる)。SDの `.html` は `text/plain` で返し、本体のページとして動かさない。
  ページはSDの名前を必ず `textContent` で入れる(`innerHTML` を使わないことをホストテストで見ている)。
- 画面に「暗号化しない送り方です。信頼できるWi-Fiで使ってください」と出す。TLSのサーバにするのは重い(BearSSLのサーバ側・証明書の扱い)ので見送った。

### 動き(`FileShareFunctions`)

- **SDに触るのは1コア目の `loop()` だけ**(画面の `onUpdate()` から `Update()`)。USBドライブと違って書き手が1つなので、
  **SDの取り上げ(`SD_usable=false`)は要らない**。ログ・Luaのバックグラウンドも止めない。`SD_usable` が偽の間は503。
- **1フレームに `kBudgetMs`=12ms だけ**、読む→SDへ書く(または読む→送る)を4KB(`kIoBytes`、SDのセクタ8つ)ずつ回して戻る。画面は描き続ける。
  送るのは送り手の窓に入る分だけ(実機は `WiFiClient::availableForWrite()`。それより多く渡すと `write()` が空くまで待つ)。PCは `MSG_DONTWAIT`。
- **接続は同時に1本**。来た順に1つずつ相手をし、1つの要求ごとに閉じる(`Connection: close`)。ページのJSもアップロードを1つずつ順に送る。
- **アップロードは `<パス>.part` へ書き、全部届いたら置き換える**(SdFatの `rename()` は行き先があると失敗するので先に消す)。切れた・10秒止まった(`kIdleTimeoutMs`)・
  SDに書けない(507)・画面を閉じた・ロックしたら `.part` を消す。中途半端なファイルが本物の名前で残らない。
  送り先のフォルダが無ければ409(作らない。フォルダごとのアップロードは第2段)。空き容量は前もって比べない(FATを全部読むので大きいカードで数秒止まる)。書けなければ507。
- **断った要求の本文は2秒まで読み捨ててから閉じる**(`Phase::Drain`)。読まずに閉じると相手のTCPがリセットになり、ブラウザに409等の理由が届かず「送れませんでした」になる。
- 使っているファイルの保護: `path_busy`(boot/ が差す)。今はミュージックで鳴らしている間、`/music` の中と `/music` を含むフォルダの書き換え・削除・移動を409にする
  (曲ごとではなくフォルダごと。どの曲が開いているかを外から引く口が無いため)。この画面が前にいる間は、ほかのシーンは止まっているのでそれ以外は気にしない。
- **閉じたときに何か書き換えていたら `sd_changed`(boot/ が差す。USBドライブの `sd_remounted` と同じもの)**を呼び、
  `LuaAppScanner::Scan()`+`PruneMissing()`・`AppPackage::InstallPending()` でランチャへ反映する。
- サーバの持ち物(要求の見出し4.5KB・送受の溜め場所4KB・パス等、約9KB)は `Start()` で `new` し `Stop()` で返す。常に持つのは最近の操作4行(約0.8KB)とキー等だけ。
- ランチャの登録簿は、このアプリを足したところでPCのSD(Luaアプリ17本)と合わせて40件ちょうどになり、
  新しいLuaアプリが入らなくなったので `AppFunctions::kMaxApps` を40→48へ広げた(+約1.5KBのstatic RAM)。

### 画面(`FileShareScene`)

左に「ブラウザで開いてキーを入れる」とキー(大きい字)、右にキー付きのURLのQR(99px)。その下にURL(IPと `<名前>.local`)を横いっぱいに、
今の転送(`↑ 45% 1.2MB/2.6MB 名前`。長い名前は後ろが切れるので割合を先に)、最近の操作(画面に入るだけ、4つまで)、下の端に注意書き。
Wi-Fiに繋がっていなければURLの代わりに赤で「Wi-Fiに繋がっていません」(繋がれば出し直す)。開いている間は `KeepAwake()`(眠るとWi-Fiが積極的な省電力になり遅くなる)・`keepForeground()`。

### 大きさ(実機ファーム、2026-10-27)

静的RAM 131,544→134,140B(+2.6KB。うち登録簿の拡張が約1.5KB)、フラッシュ 2,223,872→2,246,056B(+22.2KB。うちページ7.4KB)。

### PC/Webビルド

PCビルドは `http://127.0.0.1:8082/` で開ける(`PICOOS_SHARE_PORT` で変更。母艦の外からは開けない)。`PICOOS_SHARE_KEY`(8文字)でキーを決められる(curlで自動で確かめる用、実機には無い)。
Webビルドでは使えない(「Web版では使えません」)。
