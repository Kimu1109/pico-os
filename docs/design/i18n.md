# 表示言語の切り替え(i18n) (2026-10-31)

日本語のUIを英語でも見せる仕組み。Webビルドを海外の人にも触ってもらうのが最初の目的。
**2026-11-05から、表示言語はビルド時に1つだけ選ぶ**(下の「ビルド時に選ぶ言語」。設定アプリ・user.cfg・`--lang` での切り替えは廃止)。
中身は `src/system/I18n_Functions.hpp`(段1 system。下の段の `apps/<機能>/` 直下からも使える)。
英語の版の引き当ては `I18n_Functions.cpp`(SDもログも使わない。TR() を使うどのファイル・ホストテストからもリンクされる)。

## 考え方: 日本語の原文をキーにする

gettext と同じく、**画面に出す日本語の文字列そのものを `TR()` で包む**だけにした。

```cpp
label->setText(TR("設定"));
snprintf(buf, sizeof(buf), TR("バックグラウンド: %d件"), n);
```

- 文字列ごとに ID(列挙)を振る形にしなかったのは、2,000件を超える日本語の文字列を少しずつ移すため。
  コードは日本語のまま読め、**訳の無い文字列・まだ包んでいない文字列は日本語のまま出る**(英語のときに一部だけ日本語が混じる)
- キーは原文の FNV-1a(32bit)。`TR()` はコンパイル時に数える(`std::integral_constant` で定数式を強いる)ので、
  実行時は英語の版で二分探索1回、日本語の版は原文そのもの(関数も表も無い)。
  表は1件8バイト(ハッシュ+訳へのポインタ)+訳の文字列で、フラッシュに置く(RAMは使わない)
- `TR()` の結果は printf の書式にそのまま渡せる(`__attribute__((format_arg))` で -Wformat が原文の書式で確かめる)
- 返すのはフラッシュの定数へのポインタなので、コピーせず持ってよい

### 包めないもの(`TR_NOOP()` と `I18nFunctions::Tr()`)

`TR()` は呼んだときの言語で決まるので、**名前空間の静的な表の初期化子では使えない**(起動前に評価され、ずっと日本語になる)。
表には `TR_NOOP("…")`(値は原文のまま。script/codegen/i18n.py に拾わせる印)で並べ、使う所で `I18nFunctions::Tr(表[i])` する。
曜日(`MonthGrid`・ホーム画面のウィジェット)・スリープの選択肢・ホーム画面のウィジェットの種類名・テンキーの「決定」がこの形。

### アプリの名前は登録名を変えない

アプリの登録名は `launcher.cfg`・`pico.launch_app`・通知の送り主で**識別子として使っている**ので、日本語の原文のまま登録する
(`App_List.cpp` は `Register(TR_NOOP("時計"), …)`)。訳すのは見せる所(ランチャのタイル・長押しのメニューの見出し・
設定の「隠したアプリ」)の `I18nFunctions::Tr(entry->name)` だけ。Luaアプリの名前は表に無いのでそのまま出る。

### 訳さないもの

- ログ(`LOG_*`)・設定ファイルに書く文字列(`launcher.cfg` のコメント等)・比較に使う文字列
- かな漢字変換・キーボードのかなの配列(日本語を打つための部品)

## 訳の置き場所と生成物

| もの | 中身 |
|---|---|
| `i18n/en.po` | 人が書く訳(gettext の .po の一部。Poedit でも開ける)。`#:` は原文を使うファイル |
| `src/system/I18n_Table_En.cpp` | 生成物(hash の昇順の表)。手で直さない |
| `script/codegen/i18n.py` | `update`(src/ から拾って .po を更新し、表を作り直す)/ `--check`(CI)/ `missing en`(訳の無い原文の一覧) |

- `TR()` を足したら `python3 script/codegen/i18n.py update`。.po に空の `msgstr` が増えるので訳を書き、もう一度 `update`
- `--check` は CI(`host-tests.yml` の「層の決まり」)で回る。.po・表が src/ と食い違う、**訳の書式(`%d` 等の並び)が原文と違う**、
  ハッシュが衝突する、のどれかで落ちる。訳の無い数は表示するだけ
- `%%` を含む訳で `% o` のように空白の後に書式の文字が続くと書式として数えられる(`--check` が落ちたら言い回しを変える)
- src/ で使われなくなった原文の訳は `update` が捨てる(git の履歴に残る)

### 訳の書き方

- 画面は240px幅が基本。**原文の幅に近い短い言い方を選ぶ**(英語は日本語より横に長くなりがち)。
  設定のタブは5つで1つ40px前後なので「LCD」「Audio」、Wi-Fiの5つのボタンは「Del」のように詰めた
- 幅を決めたボタン(`Button::setW`)と `TabBar` は、入りきらない英字を**横だけ縮めて**収める(最後の手段。1ビットのフォントは
  縮めると字が欠けるので、見て崩れていたら訳を短くする)。`TabBar` は空白のある訳を空白で2行に折り返す
- 同じ原文は1つの訳しか持てない(gettext の msgctxt は無い)。場所で言い分けたいときは原文を変える
- 英語のPCビルド(`-DPICOOS_LANG_EN=ON`)の `--shot` で見た目を確かめる(下)

## ビルド時に選ぶ言語 (2026-11-05)

表示言語はビルドごとに1つだけ選び、実行時には切り替えない(利用者の判断。選ばなかった言語の文字列をフラッシュに入れないため)。
`src/config/Lang_Config.hpp` の `PICO_LANG_EN`(既定0=日本語、1=英語)。`PICO_LANG_JA` はそこで決まる(外から渡すとエラー)。
ハードウェア機能(`PICO_HW_*`)・内蔵アプリ(`PICO_APP_*`)と同じ形で、`#if` で読むファイルはこのヘッダを自分で include する(`check_layers.py` が見張る)。

| 版 | `TR("…")` の中身 | フラッシュに入らないもの | 例 | Flash(2026-11-05) |
|---|---|---|---|---|
| 日本語(既定) | 原文そのもの(`Src()`。インライン) | 英語の訳の表 `kTableEn` | `pio run -e rpipico2w` | 2,309,100 B(−64.9KB) |
| 英語(`PICO_LANG_EN=1`) | 表の二分探索(`LookupNoSrc()` → `LookupHash()`) | `TR()` の日本語の原文 | `pio run -e rpipico2w_en` | 2,318,556 B(−55.4KB) |

廃止前(実行時に切り替えられた版)は 2,373,956 B で、差はそれとの比較。静的なRAMは日本語の版で 1,352 B 減った(`AppEntry::local_name` を持たない分)。英語の版の firmware.bin に `TR()` の原文(例「ネットワークが削除されたので保存しませんでした」)が無く、
日本語の版に訳が無いことを `grep -c` で確かめた。

- **英語の版の `TR()`**: 原文のリテラルを参照しない `LookupNoSrc(hash, s)`(`always_inline` で `LookupHash(hash)` を呼ぶだけ)へ展開する。
  原文は `format_arg` で -Wformat に書式を見せるためだけに受け取り、インライン化で消えるので `.rodata` に残らない。
  引き当ては表だけなので、**訳の無い原文も表に入れる**(`script/codegen/i18n.py` が原文のまま書く。今は訳し漏れ0件)。
  表に無いハッシュ(表が古い。CIの `--check` が落とす)は `""`。表の末尾に番兵(`0xffffffff, nullptr`。数に入れない)
- **日本語の版の `TR()`**: `Src(hash, s)`(`always_inline`・`format_arg`)で原文を返すだけ。ハッシュは数えるので、`TR()` に
  リテラル以外を渡すと日本語の版でもコンパイルエラーになる(英語の版を壊さないため)。`Tr()` も原文を返すだけのインライン
- `I18nFunctions::Current()` は `constexpr`(`kLang`)。`Setup()`・`SetLanguage()`・`I18n_Setup.cpp`・`NativeName()`・`FromCode()` は消した
- **廃止したもの**: 設定アプリの「他」タブの「言語/Language」(行を詰めた)・`/sys/user.cfg` の `language`(書いてあっても読まない)・
  PCの `--lang` / `PICOOS_LANG`・Webの `?lang=` とブラウザの言語・公開サイトで選んだ言語(`picoos-lang`)を本体へ渡すこと。
  公開サイトのページ(landing / download / shell / store)の JA/EN は**ページの文だけ**を切り替える。Web版の本体は日本語の版
- **アプリの名前**: `AppEntry::local_name`(app.cfg の `name_en`)は英語の版にだけ持つ(日本語の版は48件で約1.1KBのRAMが減る)。
  `LuaAppScanner` は `name_<ビルドの言語>` だけを読む(日本語の版は `name` そのもの)。`SetLocalName(index, name)`
- **Luaアプリ**: `pico.lang()` はビルドの言語、`pico.tr()` は `lang/<ビルドの言語>.lua` を引く。英語で書いたアプリは `lang/ja.lua` を置けば日本語の版で訳される
- **アプリストア**: catalog.tsv の訳の列は今までどおり、ビルドの言語のものだけ読む(`AppRepo::ParseCatalogLine(…, Current())`)
- **残るもの**: `TR_NOOP()` の原文(アプリの登録名は `launcher.cfg` 等の識別子なので消せない)・ログの日本語・設定ファイルのコメント。
  **フォント(日本語の字形)とかな漢字変換・かなの配列は言語と関係なく残す**(ファイル名・Web・Luaアプリの日本語を表示・入力するため)
- 常駐のウィジェット・ステータスバー・最初のシーンも、起動から最後までビルドの言語(言語が変わることが無い)
- PCビルドは `cmake -DPICOOS_LANG_EN=ON`(別のビルドフォルダ)。CIはナイトリー(`nightly.yml`)で `rpipico2w_en` も作る(2026-11-06にPRから移した)。
  ナイトリー・安定版・Webからの更新の一覧は日本語の版だけ(利用者の判断。英語の版は各自ビルド)。Web版も日本語の版だけ
- ホストテストは日本語の版で作る。`i18n_test`(core)が日本語の版、`i18n_en_test`(core)が英語の版
  (`PICO_LANG_EN=1` で作り、`I18n_Functions.cpp` と表をその定義で自分に入れる)。Luaの `pico.tr` は `lang/ja.lua` で確かめる(`lua_ext_test`)
- ファームの更新(.pfw)は版を区別しないので、言語の違う本体へ送ると表示言語が変わる

### 見た目で気づいたこと

- 1行のラベルに入りきらない文は後ろが切れる(日本語でも同じ)。訳はなるべく短くした
- 同じ原文は1つの訳しか持てないので、「録音」はアプリ名もボタンも「Record」

### 英語の語の切れ目での折り返し (2026-10-31)

`Label::relayout()`(と placeholder の折り返し)は、英字の語(空白以外の ASCII が続くところ)の頭で語の幅を測り、
今の行に入らず次の行なら入るときは語の前で行を変える(`Label.cpp` の `WordWrapper`)。

- 日本語(ASCII 以外)は今までどおり1文字ずつ折り返す。日本語と英語が混ざっても、英字の語だけが切れずに残る
- 1行より長い語(URL・長いパス)は今までどおり文字の途中で切る
- 行末で溢れた空白は前の行の後ろへぶら下げ、次の行の頭へ送らない(2つ目以降の空白は折り返す)
- 語の幅を測る分だけ `textWidth()` が増えないよう、ASCII の文字幅を `relayout()` の間だけ覚えておく
- 入力欄(Textbox)・MarkdownView も同じ `Label` なので、英語の文書・入力も語の切れ目で折り返す
- `label_test` に英語・長い語・溢れた空白・日本語と英語の混在の折り返しを足した

### タブはアイコンに (2026-10-31)

英語では「Display」「History」のようにタブの文字が入りきらないので、絵で伝わるタブは文字をやめて
アイコンにした(`TabBar::addTab(IconID, label)`。日本語の画面も同じ絵になる)。label は描かず `getLabel()` で読めるだけ。

| 画面 | タブ |
|---|---|
| 設定 | Wi-Fi(電波)・画面(`Display`)・音(`VolumeHigh`)・時刻(`Clock`)・他(`Dots`) |
| 電卓 | 電卓・グラフ(`ChartLine`)・変換(`ArrowsExchange`)・進数(`Binary`)・履歴(`History`) |
| 時計 | 時計・タイマー(`Hourglass`)・ストップウォッチ(`Stopwatch`)・アラーム(`Alarm`) |
| TODO | 今日(`CalendarEvent`)・7日間(`CalendarWeek`)・すべて(`List`) |
| 通知 | 履歴(`History`)・予約(`CalendarTime`) |

- アイコンは tabler から13個を足した(`script/codegen/generate_icons.py` の末尾。全サイズ生成でフラッシュ約6.7KB)。24px・16pxとも目視で線は欠けていない
- 大きさはタブの高さで決まる(上下に2pxずつ取れれば24px、無理なら16px)
- 時計の「デジタル/アナログ」は合う絵が無い(tabler に digital の時計が無い)ので文字のまま。2つだけで幅に余裕がある
- Lua の `pico.tab_add` は今までどおり文字のタブ

## Luaアプリ (2026-10-31)

利用者向けの説明は `lua-api-doc/content/api/system/i18n.md`。

- **`pico.lang()`**: `"ja"` / `"en"`
- **`pico.tr(text, ...)`**: アプリの `lang/<言語>.lua`(「原文 → 訳」の表を `return` するだけ)から引く。表に無ければ原文。
  引数を足すと `string.format(訳, ...)`。C++ の `TR()` と同じく原文がキーなので、英語で書いたアプリに `lang/ja.lua` を置いてもよい
  (`src/lua/LuaEngine_I18n.cpp`)
  - 表は最初の `pico.tr()` で読み、`registry.pico_lang` に言語コードと一緒に覚える。(言語はビルドで決まるので、覚えた表を読み直すことは無い)
  - 表のファイルは**空の環境**で実行する(`pico.*`・アプリのグローバルに触れない)。32KBまで。壊れていたらログに警告して原文のまま
- **`app.cfg` の `name_en`**(一般には `name_<言語コード>`): その言語でランチャ・長押しのメニューに出す名前。
  英語の版だけ `AppEntry::local_name`(24B。48件で約1.1KBの常駐RAM)に持ち、
  `AppFunctions::DisplayName()` がビルドの言語で選ぶ。`name` は識別子なので言語で変えない
- **OS側のLuaの画面**(エラーの画面の見出し・打ち切りの理由・デバッガの画面・バックグラウンドの状態・ダイアログの既定のボタン)と、
  `pico.*` が2つ目の戻り値で返すエラー文(「メモリが足りません」等)は `TR()` で訳す。
  `luaL_error` の文(引数の誤り等、アプリの作者向け)・JSONの解析のエラー・シリアルのデバッガの出力・同梱モジュールの `error()` は、
  日本語のAPIの説明と揃えるため訳さない
- 同梱アプリ: 20個すべてに `name_en`。**天気を除く19個**は `pico.tr` と `lang/en.lua` で画面も英語になる(2026-10-31、原文は合わせて約580件)。
  天気は日本の天気予報のAPI(気象庁の地域・日本語の予報文)を見るアプリなので、利用者の判断で日本語のまま(画面は訳さない)
- 訳さずに残したもの: ファイルのパス・`pico.log` の文・`error()`(作者向け)・JSONの往復の確かめに使う値(動作確認の「たろう」)・
  日本語の字を描く速さを測るための文(実機チェックの「日本語の文字ABC123」)
- `..` でつないだ文は、間に値が挟まるものを書式へ直した(`pico.tr("保存できるのは%s件までです", n)`)。数は `%s`(`..` と同じ見た目。
  整数でない数を `%d` にすると string.format がエラーになるため)。「接続中: 」のように頭に付くだけのものはそのまま
- **`python3 script/codegen/i18n.py lua <アプリのフォルダ>`**: アプリの `pico.tr("…")` を拾って `lang/en.lua` を書き直す(訳はそのまま残し、
  訳の無い原文は `-- TODO ["原文"] = "",` の行で足す。TODO の行は表に入らないので原文のまま出る)。
  `--check`(CI)は `lang/` を持つ同梱アプリについて、訳し漏れ・書式の食い違い・`lang/en.lua` の古さも見る
- Luaのテストの偽物(`script/host_test/lua/pico_mock.lua`。`picoos lua-test` も使う)に `pico.lang`/`pico.tr` を足した。
  既定は日本語(原文のまま)。`mock.install{ lang = "en" }` なら偽のSDの `lang/en.lua` を引く
- アプリストア(`kimu1109/pico-os-apps`)の公式アプリは、作者の鍵で署名し直して版を上げないと配布物へ入らない(pico-os-apps で版を上げて `build_app_repo.py sign-changed`。lua-apps.md「標準Luaアプリの置き場所」)。
  同梱の版は 2.0.0 のまま(ホストテストが 2.0.0 を前提に「新しい版」を作るため)なので、配るときに版を上げる

## アプリの説明とアプリストア (2026-10-31)

Luaアプリの説明(app.cfg の `description`)は、本体ではアプリストアにだけ出る(ランチャには出ない)。
名前の `name_en` と同じ形で **`description_en`**(一般には `description_<言語コード>`)を足し、ストアの一覧に載せて運ぶ。
形の取り決めは `docs/spec/APP_REPO.md`「訳」、利用者向けは `lua-api-doc/content/api/system/i18n.md`。

- **運び方**: catalog.tsv の13列目(12列目の `min_os` の後ろ)から `name_en=…` / `description_en=…` の列で足す(`build_app_repo.py` の `catalog_line()`)。
  `min_os` を読む本体が訳を `min_os` と読み違えて行を捨てないよう、訳を載せる行は `min_os` の列を必ず置く(条件が無ければ `-`)。
  古い本体は13列目からを読まない(前からの取り決め)ので、そのまま今までどおり日本語で出る。別のファイル(言語ごとのカタログ)にしなかったのは、
  署名・取得・serial の守りを1つの一覧のまま使えるため
- **1行640バイト**: 古い本体はそれより長い行を読み飛ばす(アプリが一覧から消える)ので、本体の上限を上げずに、作る側が訳を収める
  (説明の訳を切り詰める)。同梱の20個は最長564バイト(`min_os` の列を含む)で、切り詰めずに入る
- **本体のRAM**: `AppRepo::ParseCatalogLine()` が**今の言語の訳で `name`/`description` を置き換える**だけなので、
  `Entry` は増えない(言語ごとに持つと40件で約9.6KB増える)。
  `name` は表示だけに使う(インストール先は `dir`、見分けは `id`)。パッケージ(.papp)の通知の名前も今の言語になる
- **ストアの画面**: 選んだアプリの欄は4行しか無く、説明が切れて見えなかった(日本語でも同じ)ので、`ScrollContainer` に入れて
  上下のドラッグで読めるようにし、説明を作者・権限より前に置いた(`StoreScene::setDetail()`)
- **Webのページ**: `render_card()` が訳を `data-en` に入れ、`store.html` が英語のときに差し替える(日本語へ戻すときは覚えた原文へ)。
  `data-search` には訳も入れるので、どちらの言語でも探せる。pico-os-apps の `web/store.html` と `script/` は写し直しが要る
- **同梱アプリ**: 20個すべてに `description_en` を足した。公式アプリの配布物へ入るのは、次に版を上げて `sign-changed` したとき(2026-11-07 の統一で全部の版を上げた)
- 本体の `LuaAppScanner` は説明を持たない(ログに出すだけ)ので、`description_en` は読まない(知らないキーとして無視される)
- ホストテスト: `app_repo_test`(訳の列の読み方・言語ごとの置き換え・知らない列・列の数の上限・切り詰め)、
  `app_package_tool_test`(カタログの列・640バイトに収める切り詰め・Webのページの `data-en` と探す文字)
- 確かめ方: `build_app_repo.py build` で作った catalog.tsv を `sdcard/sys/store/` に置き(`state.cfg` の `url` を既定に)、
  `--app ストア --tap 60,85@60:5` を英語のPCビルドで撮る。Webのページは `site` の出力を Playwright の `locale` ja/en で開いて切り替えた

## Wi-Fi転送のページ (2026-10-31)

PCのブラウザで開くページ(`src/net/File_Share_Page.html`)は、**ブラウザの言語**(`navigator.language`。`ja` 以外は英語)で決める。
本体の言語の設定は見ない(ページを開く人はPCの前にいて、本体の言語とは限らない)。

- 文は日本語の原文を `T()` で包み、英語はページの中の `EN` の表から引く。`%s` は後ろの引数で順に埋める
- 静的な文字(見出し・ボタン)は `data-t` の付いた要素の `textContent` を読み込み時に書き換える(`innerHTML` は使わない。`file_share_test` が見張る)
- 本体が返す誤りの文(`FileShare_Functions.cpp` の `RespondText`。日本語のまま)も同じ表で訳す。表に無い文は日本語のまま出る。
  本体の側に誤りの文を足したら、ページの `EN` にも足す
- PCビルドでは `PICOOS_SHARE_KEY=testkey1` で鍵を決め、`http://127.0.0.1:8082/?k=testkey1` を Playwright の `locale` を変えて開いて確かめた

## 通信とパーサーの誤りの文 (2026-10-31)

`net/`(HTTP・TLS・MQTT・WebSocket・キャプティブポータル)と `util/` の JSON/XML の読み手が返す誤りの文(約90件)も `TR()` で訳す。
画面の「取得できません: 接続できない」のような文の後ろ半分や、Lua の `pico.http_request` の `error` に出るもの。

- `util/` は段0(base)で `system/` を読めないので、`system/I18n_Functions.hpp` だけを段0に置いた(`check_layers.py` の `FILE_LAYERS`。
  中身は宣言とハッシュだけで依存なし。引き当ての `I18n_Functions.cpp` は system のまま)
- **誤りの文で分岐しない**: Spotify の Lua が `err == "書き込みに失敗"`(16KiBを超えたらSDへ保存して取り直す)と文で見分けていたので、
  `pico.http_request` の `info.too_large`(メモリで受ける本文が16KiBを超えて失敗したとき true)を足して、それで見分けるようにした
- 設定ファイルへ書くコメント(`Wifi_Profiles.cpp`)・ログ・`static_assert` は訳さない
- `run_net.sh` は .cpp を1本ずつ並べるので、`I18n_Functions.cpp` と `I18n_Table_En.cpp` を足した(#225 から `TR()` を使うアプリの通信の
  中身もここで組むようになっていたため)。`run_mem.sh` は `TR()` を使うファイルを組まないので変えていない

### スマホからのWi-Fi設定のページ

AP設定モードのページ(`net/Setup_Portal.cpp`)は本体が作るHTMLなので、**スマホの `Accept-Language`** で選ぶ
(`ja` で始まれば日本語、ほかの言語は英語、見出しが無ければ日本語)。本体の言語の設定は見ない(Wi-Fi転送のページと同じ考え)。
本体の言語で決まる `TR()` は使わず、日本語と英語の文を並べて書いて要求ごとに選ぶ(`Txt(ja, "…", "…")`)。`setup_portal_test` に英語の場合を足した。

## GitHub Pagesのページ (2026-10-31)

公開サイト(`site/` の landing / download / store と、`pc/web/shell.html`(Playground))を日本語・英語で切り替えられるようにした。
**Lua APIリファレンス(`lua-api-doc/`)と `docs/` の文書は日本語のまま**(利用者の判断)。

- 言語の決め方: `?lang=ja|en` > このブラウザで選んだ言語(localStorage `picoos-lang`。同じオリジン `kimu1109.github.io` なのでストアとも共通) >
  ブラウザの言語(`ja` 以外は英語)。`?lang=` で来たときも覚える。ステータスバーの `EN`/`JA` で切り替える
- 4ページの `<head>` に同じ `I18n` の小さなスクリプトを置く(1ファイルずつ単独で配るので共通のJSにしない。直したら4つ合わせる)。
  日本語はHTMLに書いたまま、英語の表だけをページの末尾に持つ。要素は `data-i18n="鍵"`(中身を差し替え)、属性は `data-i18n-attr="属性=鍵;…"`、
  JSで作る文は `I18n.t("日本語", "English")`。ダウンロードのページは言語を変えたら版の一覧を作り直す
- Playground は切り替えると `?lang=` を付けて読み込み直す(JSで作ったボタンの文も作り直すため)。
  **2026-11-05から本体(Web版の pico-os)はこの言語に従わない**(日本語の版。「ビルド時に選ぶ言語」)
- ストアのカードの権限の印は `build_app_repo.py` の `render_card()` が `data-i18n="perm.<名前>"` を付ける。アプリの名前・説明は作者が
  app.cfg に書いた訳(下の「アプリの説明とアプリストア」)があれば `data-en` に置いて差し替える。
  pico-os-apps の `web/store.html` の写しは写し直しが要る
- 確かめ方: `_site` と同じ並びに置いて `python3 -m http.server` で開き、Playwright の `locale` を ja/en にして、英語のときに日本語の文字が
  (ストアのアプリの文を除いて)残らないこと・ボタンの往復で元に戻ること・375px幅ではみ出さないことを見た
