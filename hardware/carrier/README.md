# pico-os キャリアボード v0.3

Raspberry Pi Pico 2 W と、今までジャンパワイヤでつないでいたモジュールを1枚の基板に載せるための基板(KiCad 8、2層)。
**基板自体はほとんど機能を持たず、モジュールをつなぐだけ**。ピンの割り当てはファームの `src/consts.hpp` と同じ。

> **今の状態: 全ネットを配線済み。DRC(回路図との照合込み)・ERC とも違反 0**(下の「配線」)。発注前に下の「確かめること」を見る。
> 部品の形とピンの並びは、商品写真・寸法図・実物で確かめた(2026-11-02)。

設計の経緯と決めたことは `docs/design/carrier-board.md`。

## 基板の形

- 外形 100 x 160 mm、2層、1.6mm。表から見て上の中央に液晶、下に Pico 2 W が横向き(USBが左、アンテナが右の切り欠き)。
  詰め込まず、モジュールどうしは 8〜12mm 前後・液晶の14ピンの列と Pico の間は約34mm 空けた(v0.3。v0.1 は 64x128、v0.2 は 80x140 で、まだ窮屈に見えた)。
  USBのケーブルはソケットで浮いた Pico の上から挿す。
- **表**: 液晶(MSP2807)だけ。14ピンと4ピン(SD)をピンソケットで受け、四隅のM3の穴(液晶の穴と同じ位置)をスペーサーで留める。
  液晶の裏のSDスロットは表から見て左の縁にあるので、液晶と基板のすき間からカードを差す。
- **裏**: Pico・LiPo SHIM・PCM5102A・MAX98357A・マイク・RTC・コネクタ・ジャンパー。
- **アンテナの下は基板を切り欠いた**(右下の切り込み)。切り込みの上下の細い所にもGNDのベタは敷かない。
- GNDのベタは両面。ネットクラスの決まり: 電源(GND/VSYS/VBUS/+3V3/LCD_VCC/PCM_VCC/GROVE_VCC)は1.0mm、ほかは0.4mm、間隔は0.3mm。

## 配線

`tools/route_carrier.py`(KiCad の Python だけで動く格子の迷路探索)で全ネットを引いた。小さくするより確実に動くことを優先し、余裕を持たせた:

| | 値 |
|---|---|
| 信号の線 | 0.5mm |
| 電源の線(VSYS/VBUS/+3V3 など) | 1.0mm(Qwiic の細い端子へ入る所と、通れなかった LCD_VCC/PCM_VCC/GROVE_VCC の枝は 0.5mm) |
| 銅どうしの間隔 | 0.5mm(Qwiic の 1mm 間隔の端子の周りだけ 0.4mm。DRC の決まりは 0.4mm)。空きがあれば別のネットから 1.5mm 以上離れた所を通す |
| 基板の縁から | 1.5mm |
| ビア | 外径0.8mm・穴0.4mm |
| 層の使い方 | 表は横、裏は縦を主に使う |

GND は両面のベタと 0.5mm の線の両方でつないだ。端子の上と近くにはビアを置かない。線で区切られたベタの島に掛かる GND の端子は、ベタへ全面でつないだ(サーマルの橋が島に掛かる警告を消すため)。

液晶を留める M3 の穴の周り(半径3.5mm)は、スペーサーとネジ頭の下になるので線とビアを通していない(GND のベタだけ)。
Grove(J1)と Qwiic(J2)の差し口は基板の右の縁を向く。シルクは文字の高さ 1mm 以上・線 0.15mm 以上(JLCPCB の目安)。

手で直すときは KiCad で `pico-os-carrier.kicad_pcb` を開き、直した後に

1. `B` キーでベタを埋め直し、DRC(回路図との照合を入れて)を通す。
2. `python3 hardware/carrier/tools/check_pins.py` で結線がファームと合っているかを見る。

**手で直し始めたら `gen_carrier.py` / `route_carrier.py` は回さない**(配置と配線が作り直しになる)。
作り直すときの順は `gen_carrier.py` → `route_carrier.py`(数回やり直して全部つながった回を残す。十数分かかる)→ `export_jlcpcb.py`。

## JLCPCB への発注

`python3 hardware/carrier/tools/export_jlcpcb.py` で `fab/pico-os-carrier-v<版>-jlcpcb.zip` を作る(ガーバー7枚・PTH/NPTH のドリル・穴の地図)。
JLCPCB の注文画面で zip を上げ、次のように選ぶ(ほかは既定のまま):

| 項目 | 値 |
|---|---|
| Layers | 2 |
| Dimensions | 100 x 160 mm(zip から自動で読まれる) |
| PCB Thickness | 1.6 mm |
| Surface Finish | HASL(鉛フリーでも可) |
| Outer Copper Weight | 1 oz |
| Min via hole size/diameter | 0.3mm/(0.4/0.45mm) 以上なら何でもよい(この基板のビアは 0.4/0.8mm) |
| Remove Order Number | 好みで(番号を入れたくなければ指定する) |

穴を2列の端子の間に置いていないので、どの設定でも追加の費用は掛からない見込み。部品の実装(PCBA)は頼まない前提。

## 確かめること(実物でしか分からないもの)

- **LiPo SHIM の向き**: 文字の面が Pico の裏と向き合う(Pimoroni の説明)ことと、JST・ボタンが文字の無い面にある(商品写真)ことから、
  部品面から見た穴の並びを Pico の鏡映にした。**逆に挿すと VBUS/VSYS が GP0〜GP5 につながる**ので、キャリアボードに印刷した
  「BTN」(ボタンの端)「JST」(電池コネクタの端)に合わせ、ボタンと電池コネクタの面を外に向けて挿す。SHIM 自体の「+」「-」は電池の極性の表示。
  ピンは文字の面から出す(部品の面を上にしてブレッドボードに挿せる向き)。利用者の物はこの向き(2026-11-03 に確認)。
- **DS3231 のピンの向き**: 商品写真の物は **L字のピン**が付いている。この基板は「まっすぐなピンをチップの面から出し、電池の面を外へ向ける」形なので、
  届いたら L字のピンを外してまっすぐなピンに付け替える(2026-11-03 に決めた。基板はそのまま使える)。
- **Wii の変換基板は J2 を使わずジャンパワイヤでつなぐ**(2026-11-12 に利用者と決めた。SH 4ピンの表面実装コネクタが手に入りにくいため)。
  DS3231 の反対の端の4ピン(SCL/SDA/VCC/GND。I2C がそのまま出ている。VCC は 3.3V)と変換基板の同じ名前の端子を結ぶ。
  キャリアボードには DS3231 の4ピン側の穴が無いので、4ピン側のピンは**電池の面から上へ出す**(下向きに付けると基板に当たって浮く)。
- PCM5102A は商品写真から読んだ位置なので、端子の位置(左の列は縁から約1.3mm、上の列は左の縁から約7mm)を実物で測っておくと安心。
- PCM5102A のジャック(PJ-327A)の1番(差し込み検出の接点と思われる)はモジュールの上でどこにもつながっていない。イヤホンの自動切り替えに使うなら、ここから J3 へ線を引けるか実物で確かめる。
- ZS-042 は CR2032 を充電する回路(ダイオードと抵抗)が付いていることが多い。CR2032を使うなら外す。
- 確認済み(2026-11-03、利用者): PCM5102A の H3L にはんだは盛られていない。マイクは文字(SEL〜3V)の面が外、ピンはマイク本体の面から出ている。
  Pico 2 W は **WH(ピンヘッダ付き)**。ピンは下向きで、黒いサポート材は2列の間なのでソケットに当たらない。デバッグ用の3ピンは付けていない
  (WH のデバッグ用コネクタは表の面にあるので基板に当たらない)。
- 電源ボタン(SHIM)で切れるのは 3V3_EN だけ。VSYS につながる物(MAX98357A・C1・JPでVSYSを選んだ物)は電池につながったまま。
